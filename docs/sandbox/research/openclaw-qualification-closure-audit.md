### Why the transport follow-up is bounded

The 100-cycle test already uses real HTTP, not a mocked HTTP client. Its assertions wait for an empty adapter registry and confirm that FastMCP's default session manager is absent. Inspection of `WorkloadHTTP._retire` shows that it terminates the SDK transport, drains its task and waits for request handlers before removing a record; an empty registry therefore has meaningful implementation support. The audit found no demonstrated retained-session leak.

The remaining evidence task is to make SDK settlement directly observable over those cycles and identify the exact published environment. Retain read-only references or observations of SDK task completion, transport termination and stream/request settlement; do not add another production registry. The separate Gateway record already observes SDK and adapter retirement for its smaller run. The acceptance requirement is at least 100 transport sessions, not 100 Gateway turns or Bicep containers.

### Composition boundaries and retained limits

The common Python runtime baseline remains MCP 1.28.1, MAF core 1.19.0, maf-sandbox 0.46.0, Bicep 0.22.0, Docker backend 0.24.4 and Uvicorn 0.54.0. Gateway observations remain tied to OpenClaw 2026.9.7 on the recorded Windows host. The adapter source is unchanged since the MCP version update in #1711, service supervision since #1680, and the Bicep composition since #1776. Repository history and the recorded source hashes support combining these observations without claiming a rerun on current packages.

The #1850 run deliberately changed the unavailable original local image to the released Bicep AVM 0.1.0 digest, verified its release identity and retained the compiler configuration digest. Its ownership evidence belongs to that new image; the older Gateway scenarios belong to their recorded images. The combined acceptance does not qualify every scenario against one final image. #1851 used synthetic bindings and no Docker, compiler, Gateway or model. Its five direct-ASGI cases establish accounting/handler settlement separately from socket observations, and accelerated timers do not replace the separately recorded default-duration expiry case.

Active MAF close retires service state and permits surviving-client work before the closed client's outstanding future necessarily settles. In #1850, service cleanup/retirement was observed by 22.52 seconds while that future timed out at 240.01 seconds. These are observed times, not lifetime guarantees; hosts retain responsibility for outstanding client tasks. This limitation does not contradict the acceptance requirement for isolated cleanup and preserved admission.

Actual-model reasoning, prompt-injection resistance, information-flow enforcement, complete crash coverage, other host platforms, remote tenancy, an independent watchdog, latest-version compatibility and indefinite/concurrent stress remain unqualified. They remain outside #1676's finite completion criteria. A newly found defect still requires repair and its own qualification; this closure is neither unattended-operation approval nor a production-readiness claim.
