# OpenClaw Bicep qualification closure audit

> Closure audit recorded on 2026-10-11 after merged #1847. This maps the original #1676 acceptance to existing evidence; it adds no runtime qualification. The issue remains open behind two finite follow-ups. Historical reports and their `complete_matrix: false` fields remain unchanged.

## Decision and scope

Keep [#1676](https://github.com/sokolaidev/maf-extensions/issues/1676) open until [#1850](https://github.com/sokolaidev/maf-extensions/issues/1850) supplies the remaining Bicep/MAF ownership observations and [#1851](https://github.com/sokolaidev/maf-extensions/issues/1851) records the transport subset on the exact published dependency baseline. Then reconcile this matrix and close the issue if every required observation is evidenced. Another unspecified lifecycle or stress-testing tranche is not a closure criterion.

The audit inspected repository commit `e2602e5dfc35d456d66b0c346b41abb5c3434aac`, the original issue requirements, the [service acceptance matrix](../openclaw.md#acceptance-before-enabling-multiple-gateway-sessions), current test source and the merged delivery records through [#1847](https://github.com/sokolaidev/maf-extensions/pull/1847). Source inspection identifies what tests exercise; it is not a new live execution. Historical live candidates remain the candidates named in the [Gateway evidence record](openclaw-gateway-qualification.md), rather than this audit commit.

The qualified baseline is OpenClaw 2026.9.7 with its TypeScript MCP SDK 1.30.0, Python MCP 1.28.1, MAF core 1.19.0, maf-sandbox 0.46.0, Bicep 0.22.0, Docker backend 0.24.4 and Uvicorn 0.54.0, on the recorded Windows host with Linux Docker guests. These are observed historical versions, not a claim about the latest packages. The sample permits a MAF version range; reproductions must capture and enforce the selected baseline rather than assuming that a fresh resolution still chooses it. Image and compiler configuration identities remain those in each live record.

The [HTTP service tests](../../../tests/test_mcp_workload_service.py) exercise actual Uvicorn/loopback HTTP with synthetic workload bindings for most protocol cases; the body-reader-budget case directly drives ASGI. None of these establishes actual-model reasoning or unattended operation.

[#1719](https://github.com/sokolaidev/maf-extensions/pull/1719) records 158 focused passes including four live cases on candidate `176b98c438ade6534be501722f2648524d970828`, alongside the published-dependency Gateway baseline. ### Why the transport follow-up is bounded

The 100-cycle test already uses real HTTP, not a mocked HTTP client. Its assertions wait for an empty adapter registry and confirm that FastMCP's default session manager is absent. Inspection of `WorkloadHTTP._retire` shows that it terminates the SDK transport, drains its task and waits for request handlers before removing a record; an empty registry therefore has meaningful implementation support. The audit found no demonstrated retained-session leak.

The remaining evidence task is to make SDK settlement directly observable over those cycles and identify the exact published environment. Retain read-only references or observations of SDK task completion, transport termination and stream/request settlement; do not add another production registry. The separate Gateway record already observes SDK and adapter retirement for its smaller run. The acceptance requirement is at least 100 transport sessions, not 100 Gateway turns or Bicep containers.

After both deliver their required observations, audit their records against this table and the original issue. A newly exposed defect must be fixed and requalified; an unmeasured scenario outside the table does not silently become a new blocker. A consolidated closure record may accept the combined evidence without rewriting historical reports or changing old `complete_matrix` values. Merging a harness without running its required live cases is insufficient.

## Explicit limits and later design work

The original #1676 completion statement explicitly separates actual-model reasoning, prompt-injection resistance, a complete crash matrix, Linux/macOS host qualification and an independent watchdog. These remain unqualified and are not requirements for closing this supervised, selected-baseline issue. No production readiness, maximum cleanup lifetime, remote tenancy, general TLS deployment or newest-version compatibility is claimed.

The later discovery cases in [#1789](https://github.com/sokolaidev/maf-extensions/pull/1789), [#1794](https://github.com/sokolaidev/maf-extensions/pull/1794) and #1847 are useful additional evidence. The latest record's originating-runtime first retry, exact backoff deadline races, delays beyond 120 seconds and concurrent discovery are unmeasured extensions, not new acceptance requirements. The same applies to arbitrary daemon storage faults, broader outages, exhaustive expiry/admission interleavings and indefinite/concurrent churn beyond the finite contract tests. Historical “remaining” paragraphs describe what was unmeasured at their date; this audit owns the current closure list.

[#1637](https://github.com/sokolaidev/maf-extensions/issues/1637) remains the research/design umbrella. After #1676, reconcile the Bicep design decisions and follow-up dispositions in [#1638](https://github.com/sokolaidev/maf-extensions/issues/1638). Then decide implement/defer/decline for additional workload/artifact tools (#1639), enforced egress/credential mediation (#1640), reusable conformance and installed-package qualification (#1641), and a full sandbox backend (#1642). The conformance design can prioritize further stress/platform scenarios; listing them here does not commit to implementing them. Finishing qualification alone does not close those design issues or the umbrella.
