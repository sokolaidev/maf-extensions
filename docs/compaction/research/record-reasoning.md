# Completed recall records with reasoning

[#2631](https://github.com/sokolaidev/maf-extensions/issues/2631) proposes removing reasoning together with the recall call and result it belongs to. The implementation requires a later genuine user request, excludes synthetic recall instructions, tool results, generated summaries and excluded users as boundaries, and retains the current carried result. A mixed group or a rich result remains protected.

Removing an old record can also change the prefix of reasoning that remains later in the conversation. Anthropic's [preserved-thinking contract](https://platform.claude.com/docs/en/build-with-claude/preserved-thinking#compact-on-the-client) makes this a separate constraint from keeping the current tool loop whole. Record replacement therefore stops before any later retained reasoning. Lossless reshapes validate a batch of eligible completed records and replace them together, with no history rescan per record; an unrelated or active reasoning group protects every record before it. This is a conservative record-selection rule, not provider-wide qualification of the other compaction strategies.

## Qualification matrix

Unit tests cover whole-group exclusion, exact value retention, completed and active turns, synthetic boundaries, later-reasoning protection, mixed content, carried results and persisted decision replay. Replay restores a previously accepted edit on exact matching sources even when later reasoning has arrived: that reasoning was produced on the compacted prefix, so restoring the original prefix would change its input. These tests do not establish service acceptance. The live results below qualify the three configured routes for their recorded models, adapters and settings.

| Route | Required probe | Acceptance evidence |
|---|---|---|
| OpenAI Responses, stateless | Request real recall calls with reasoning and encrypted reasoning replay where supported; complete that tool loop, add a new user request, replace the old recall group, and send the projected messages with `store=false`. Repeat after session serialization and restore. | Both baseline and compacted requests succeed; no orphaned reasoning, calls or results; record values remain available. Active-loop input remains unchanged. |
| Anthropic thinking | Obtain actual signed thinking and recall blocks, finish the assistant tool loop, then replace completed records. Include a later retained thinking block as a negative selection case. On models supporting binding controls, explicitly request prefix mismatch errors. | Baseline and compacted requests succeed without dropping invalid thinking to hide a prefix mismatch. Current-loop and later-prefix guard cases remain byte-for-byte unchanged on the wire. |
| Gemini | Specify the API and framework adapter, capture a real signed function call, complete the turn, replace the old record, and replay after restore. Cover the adapter's actual thought/signature representation. | Call/signature leave together, with no surviving signature attached to the wrong part; continuation and restored continuation succeed. |

Use synthetic record values only. Retain model and SDK versions, request shapes, finish reasons and usage; keep credentials and opaque provider tokens out of the public evidence. A missing reasoning/signature block is an unqualified probe, not a pass. The AG-UI history adapter drops reasoning across reconstructed runs, as the issue's comment explains, so these probes must exercise an adapter that actually replays it.

The [sanitized evidence](record-reasoning-live-2026-11-11.json) retains all three reports and request shapes. Python was 3.13.12 and `agent-framework-core` 1.24.0 throughout.

OpenAI and Claude ran on product commit `9fe573c51b1edc8b0fabb9e9a377930f61306179`, with `azure-identity` 1.26.0 and probe SHA-256 `5a9fa69f308680994a051e047126985b68c684eb9144f0e5aaa46ed601436843`. All three routes produced two actual recall calls with protected reasoning. Each loop completed without later reasoning items in the framework history before a genuine user request made the records eligible. The probe exercised lossless reshape, a merge of exactly two written records after the production reshape, and rewrite of one original completed record. Synthetic identifiers remained in the resulting record bodies and in the live continuation answers. Every operation reduced the serialized request history. Active-loop and later-retained-reasoning guards selected no records and preserved the serialized history exactly; both guarded histories were accepted by each service.

Each operation also passed after JSON serialization and restoration of messages and strategy state. Replaying decisions on the original history reproduced the compacted provider input exactly, including when later reasoning generated on that compacted input was appended before restoration. Actual outbound request bodies were checked against the framework adapter's projection. Claude's deliberate prefix mutation establishes that its successful requests were tested with binding enforcement active.

Gemini returned a thought signature on each function-call part. Its adapter represents that signature as a protected reasoning item immediately before the call, and serializes it back onto the call. The probe required exactly two signed sources, verified that reshape/merge removed both call/signature pairs, and verified that rewrite removed one pair while preserving the other signature on its original call. Calls and results remained paired. Every request used a fresh adapter, including completion of each active tool loop after JSON restoration, so an in-memory signature cache could not supply a missing signature. Later text thought summaries are framework reasoning items but are not retransmitted by this adapter; the later-reasoning guard therefore establishes unchanged projection, not Gemini prefix-binding enforcement. The final LOW/MEDIUM configuration passed; an earlier configuration trial received HTTP 400 because this resolved model does not support MINIMAL thinking.

The record merge/rewrite summarizer was a deterministic fixture retaining distinct values. These probes qualify provider acceptance and record projection/replay for the listed routes and settings, not live summarizer quality, tokenizer accuracy, streaming, all models or the AG-UI within-run case. The integrated compaction suite passed 1,499 tests; the full repository gate was not rerun for this qualification.

## Reproduce

Set `QUALIFICATION_MODEL_NAME` and `QUALIFICATION_MODEL_VERSION` to the public model metadata. For the Foundry routes, use an existing Azure CLI login authorized for inference. For OpenAI, set `AZURE_OPENAI_ENDPOINT` to the resource endpoint and `AZURE_OPENAI_MODEL` to the deployment name; for Claude, use `ANTHROPIC_FOUNDRY_ENDPOINT` and `ANTHROPIC_FOUNDRY_MODEL`. Endpoints omit the API suffix, which the probe adds. The Azure scopes are `https://cognitiveservices.azure.com/.default` and `https://ai.azure.com/.default`, respectively.

For Gemini, set `GEMINI_ENDPOINT=https://generativelanguage.googleapis.com`, `GEMINI_MODEL=gemini-flash-latest` and supply `GEMINI_API_KEY` through the process environment. Set the qualification model version to the actual resolved version; the probe refuses a response from a different version. A moving model alias requires fresh qualification when its resolution changes.

Run from the repository root, choosing an output directory outside tracked files:

```bash
uv run python scripts/experiments/qualify_record_reasoning.py --provider openai --output .local-evidence/record-reasoning
uv run --with agent-framework-anthropic==1.0.0b261022 --with agent-framework-core==1.24.0 python scripts/experiments/qualify_record_reasoning.py --provider anthropic --output .local-evidence/record-reasoning
uv run --with agent-framework-gemini==1.0.0b261106 --with agent-framework-core==1.24.0 python scripts/experiments/qualify_record_reasoning.py --provider gemini --output .local-evidence/record-reasoning
```

Each run writes only a public metrics report: request/response digests, history/tool counts, service status, usage, checks, and failure type/stage. Raw provider bodies stay in memory for wire comparisons; no raw payload file or exception traceback is written. Provider transformation details are counted without persisting or printing their contents. The retained live evidence predates this output restriction and includes sanitized request shapes derived from locally captured bodies; those raw captures are not part of the committed evidence. The adapters' private serialization helpers are version-specific; the report records the installed versions so a later adapter update requires fresh qualification.
