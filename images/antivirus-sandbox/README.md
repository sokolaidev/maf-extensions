# Antivirus image

The `antivirus` profile provides ClamAV 1.4.6, Python and official baked `main`, `daily` and `bytecode` seed databases for Linux/amd64. Its runtime has no daemon or runtime update requirement. The kind stages a fixed guest program and optional host-supplied signed updates; scanning runs with closed egress.

Build with `docker build --platform linux/amd64 -t maf-antivirus:local images/antivirus-sandbox`. Run `uv run python scripts/antivirus_qualification.py --image maf-antivirus:local --output out/antivirus` for controlled Docker checks. Set `MAF_ANTIVIRUS_UPDATE_DIRECTORY` to an immutable mirror snapshot to also exercise host updates. `--backend acas` uses the existing ACAS environment configuration and an image already imported into the sandbox group's registry; provision enough memory for ClamAV. Local Docker checks do not establish ACAS qualification.

The digest-pinned Alpine 3.24 base uses its `clamav-scanner=1.4.6-r0` package, including `clamscan`, `sigtool`, the shared engine and its utilities. Alpine owns native dependency fixes; the image still passes the repository's inventory and High/Critical vulnerability gate. Dependabot tracks the base digest. The ClamAV package pin is manually reviewed when upgrading the engine, including its signature verification and database functionality compatibility. Image redistribution must retain the upstream package license notices and corresponding-source obligations; the Python kind retains the repository's MIT license.

FreshClam fetches seeds from `database.clamav.net` in a build stage with incremental updates disabled, verifies authenticity and loadability, and retains CVDs. Their hashes, versions and build times are recorded by runtime qualification. A cached build may reuse its seed: runtime freshness comes from host-supplied updates and the host's age ceiling, never from image creation time. There is no daily antivirus image rebuild; source changes or explicit dispatch select candidate builds, while release publication follows the normal protected approval path. Published immutable digests continue to receive catalogue monitoring.

The [image release contract](../../docs/security/container-image-releases.md) applies: provenance, SBOM and completion evidence bind the image seed and engine. Host-supplied updates have separate upstream authentication and per-call identities; they are not covered by the original image SBOM. A tag's existence alone does not establish a completed release. No production or ACAS qualification is implied by a candidate build or controlled Docker checks.
