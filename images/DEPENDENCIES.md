# Container dependency ownership

Wolfi is the default suite runtime. Each workload installs only its own requirements. External image references live in Dockerfiles as explicit tags and immutable digests; JSON recipes do not repeat those references. `python scripts/container_image_inputs.py` enumerates every image and package-owned Dockerfile, including `source.Dockerfile`, `prepared.Dockerfile` and test fixtures, and rejects missing digests or unreviewed compatibility families.

The suite maintainers own dependency review and qualification for all rows below. Dependabot proposes changes; it never approves, releases or publishes an image. Review installed SBOM components as well as source declarations: a digest pins the starting filesystem, while `apk upgrade`, package repositories and source restores can still change the resolved result. Retained candidate identities, receipts and inventories bind the resulting bytes.

All archive/source exceptions remain owned by suite maintainers. Scheduled Image security and published-image monitoring provide vulnerability feedback, not automatic authenticated archive upgrades. Moving these pins to another arbitrary file format would not make them managed.

The proxy updater modules isolate their native manifests from the partial credential patch source beside them. Each `imports.go` retains the pinned upstream production and test imports, so Go tooling can resolve and tidy the complete external dependency graph without a Docker build. Regenerate it with `go run scripts/proxy_dependency_imports.go PATH_TO_VERIFIED_UPSTREAM`, then run `go mod tidy` in each dependency directory. The Dockerfiles overlay those same manifests onto the verified upstream checkout; read-only credential tests and compilation reject missing build dependencies. Updating the upstream source requires regenerating the import anchors as well as reviewing the local patch.

The Terraform and OpenTofu engine overrides and the Terraform AVM GitHub provider source-build lock pin Go JOSE v4.1.6 to address [GHSA-mgcc-cww5-fp2q](https://github.com/advisories/GHSA-mgcc-cww5-fp2q). The provider needs its own override and regenerated module/package hashes because it is compiled independently of the engine. Both proxy manifests already carry the same patched version through [#2276](https://github.com/sokolaidev/maf-extensions/pull/2276).

[Published-image monitor #2282](https://github.com/sokolaidev/maf-extensions/issues/2282) remains a release recovery task: [run 40682930923](https://github.com/sokolaidev/maf-extensions/actions/runs/40682930923) found v4.1.4 in egress-proxy 0.1.2, OpenTofu random 0.1.3, Terraform random 0.1.4 and Terraform AVM 0.1.5, including the AVM GitHub provider 6.13.0. Recovery requires new qualified releases for all four profiles and a fresh complete monitor run; retain the High/Critical gate, including unfixed findings, and close the tracker only after published-image recovery is verified.

## Update validation and evidence

Dependabot groups scheduled version updates and security updates separately. Each native manifest family has both groups; proxy Go modules and proxy images each group across the Docker and WSLC copies so their declarations can advance together. Build images retain dedicated Wolfi and Go toolchain version groups, with remaining images grouped together. Existing compatibility-line restrictions still apply.

Weekly Docker jobs cover every image directory and package-owned Dockerfile directory. Dependabot's [Docker file discovery](https://github.com/dependabot/dependabot-core/blob/main/docker/lib/dependabot/docker/file_fetcher.rb) includes non-default names containing `Dockerfile`. Shared Wolfi and Go references are grouped across directories. Native pip, NuGet and Go jobs consume the manifests the build actually reads. The [supported ecosystem list](https://docs.github.com/en/code-security/reference/supply-chain-security/supported-ecosystems-and-repositories) defines the automation boundary.

PR Image security selects affected profiles from changed file paths, so tag changes and same-tag digest changes take the same build, runtime qualification, SBOM and High/Critical scan path. It has no publishing permissions or release dispatch. The selector maps both mirrored proxy contexts to the proxy profile; parity checks bind their build inputs. Docker Sandboxes consumer qualification needs Docker credentials configured for the actor, including Dependabot secrets for bot PRs. Missing credentials are a failure, not a successful sandbox qualification.

The gate continues to reject unfixed High/Critical matches. Source/license receipts, full application/provider inventories, exact image IDs, release signatures and retained-candidate identity checks remain required. No blanket suppressions or ignore-unfixed settings are added. The release build-input record now includes non-default Dockerfiles and native dependency manifests.

Shell before/after evidence is retained in the [shell guide](shell-sandbox/README.md): the Debian candidate had 55 High findings; the tested Wolfi candidate had zero High/Critical and two Medium findings in its dated local assessment. Subsequent published Docker, ACAS and WSLC evidence is linked there. Those results do not qualify a newly rebuilt candidate or every other Wolfi image.

Issue [#2178](https://github.com/sokolaidev/maf-extensions/issues/2178) tracks migration acceptance, completed by the evidence in [#2300](https://github.com/sokolaidev/maf-extensions/pull/2300). Implementation, local builds, local updater proposals, hosted PR checks, candidate publication and production acceptance are distinct. The GitHub bot tag and digest proposals below now have successful affected-profile aggregates, including Docker Sandboxes qualification. Release approval and publication remain maintainer actions.
