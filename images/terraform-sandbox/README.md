# Terraform and OpenTofu validation images

This page describes what the validation images contain and the rules their inputs follow. To build, try, check or deploy an image, see [USAGE.md](USAGE.md).

[image.json](image.json) owns the base-image digest, platform, engine versions, download URLs, archive checksums and profile mappings. The Python [builder](build_image.py) reads that file and passes matching version metadata to Docker; [install.py](install.py) reads the same file inside the build and verifies the downloaded binary's reported version. Each image holds one engine. The initial platform is **Linux amd64**. The `builtin` profile has an empty provider mirror and supports built-in resources and local modules. The `random` profile reads its providers from the corresponding `dependencies.terraform.json` or `dependencies.opentofu.json` manifest. Downloads happen during image construction; validation has closed egress.

Both image and profile manifests require an integer schema identifier of `1` and reject duplicate JSON keys at every depth. Provider names and prerelease versions use the same manifest grammar in preparation and image builds. Provider prerelease identifiers are nonempty, dot-separated, and lowercase. Engine pins also accept uppercase ASCII prerelease letters and preserve their spelling, for example `1.16.2-RC.1`. Core version numbers and numeric prerelease components reject leading zeros; nonnumeric identifiers such as `01a` remain valid. Provider archives must target `linux_amd64`. Profiles also reject repeated provider source/version/platform identities before any download. There is no automatic latest-version lookup.

## Image identity

The image carries Docker/OCI labels `org.opencontainers.image.version`, `ai.sokol.maf.engine` and `ai.sokol.maf.engine.version`, including the actual verified binary version. `/opt/maf-terraform/engine.json` also records the engine, executable, version, platform, archive digest, binary digest and profile; it remains the launcher's runtime identity record. A missing/mismatched version build argument or a binary reporting another version fails the build. Derived prepared images inherit these labels from their base and rewrite `engine.json` to profile `prepared` with the prepared receipt's `manifest_sha256` and `policy_sha256`. A prepared mirror holds the providers unpacked: Terraform links each provider into the call instead of copying its bytes, and the launcher refuses a call that was served by copying.

The base is Python 3.13.15 slim pinned by digest in `image.json`. The installer checks every downloaded archive before extracting it, preserves engine license notices, and leaves provider licenses inside their mirror archives (in a prepared image they are unpacked beside the providers). [runner.py](runner.py) verifies the recorded binary identity and version before executing a request. Deploy the resulting image by immutable digest; a deployment owns its trusted image and provider selection.

## Approved dependency preparation

The request restrictions in this section apply to `terraform_dependencies.py`. The image installer's `random` and custom profiles use the existing checksum-verified `urllib` downloads; they consume provider URLs and digests but do not enforce manifest redirect policy, address restrictions, or the preparer's resource limits. For those guarantees, prepare dependencies with the CLI and build `prepared.Dockerfile` from a trusted empty-mirror base using `--network none`, as [USAGE.md](USAGE.md#build-a-prepared-image) shows. Base-image and engine-binary acquisition remain separate trusted image-build inputs.

The repository tool [terraform_dependencies.py](../../scripts/terraform_dependencies.py) prepares additional dependency profiles using a host-owned manifest. This is build tooling, not a public Python package API or a guest-facing download service. Run it through its CLI after `uv sync --locked`; the CLI supervises a worker under one 180-second wall-time limit, including DNS and archive processing. The CLI has no worker mode; its parent launches a private Python entry point against temporary output. Worker refusals return fixed policy decision codes to the CLI; arbitrary worker diagnostics are discarded, and unclassified failures report `preparation-failed`. The tool executes neither engines nor providers on the host. Validation still has CLOSED egress.

The example manifests pin the existing engine-specific `random` provider archives and the standalone `random_string` module example from HashiCorp's `v3.7.2` commit. The module graph is a single leaf, recorded separately from the provider lock. The selected upstream module files are preserved, including its UTF-8 configuration and ancillary import script; preparation and validation never execute that script. The module archive digest was reviewed and pinned from the immutable commit archive, not authenticated by a release signature. Provider digest pins carry forward the image guide's approved SHA256SUMS values. A provenance string is an operator assertion; the preparer verifies the pinned digest and does not verify signatures or establish signer trust.

The base must be a trusted builtin-profile image. The build refuses a nonempty base mirror, an engine mismatch, changed ZIP bytes, and any missing, additional, or digest-mismatched provider archive; it then unpacks every verified ZIP into the image, restores each extracted file's `0o755` mode, checks every extracted file against the receipt's `files` digests, and fails unless the `h1` recomputed over the unpacked tree equals the receipt's. The published mirror holds unpacked providers, which Terraform links into the call and never copies. A supplied lock whose provider hashes are `zh:`-only is no longer verified against the unpacked mirror, while `h1:` hashes still are. Tags in the local examples are conveniences: deployments must use the resulting immutable image ID/digest. Preparation refuses an existing output directory and publishes only after complete success. Preserve the output in trusted artifact storage; writable directory permissions alone do not make it immutable. Stage module files by the receipt's inventory and check their hashes, as the example does. The example rejects non-relative paths and resolved paths outside the module directory before reading; staging requires stable, trusted artifact storage. Do not mix unrelated provider mirrors into the image.

### Manifest and request contract

Only trusted host configuration supplies the manifest. Never construct it from guest URLs or attach the preparer as an agent tool. `schema` is exactly `1`, `engine` is exactly `terraform` or `opentofu`, and unknown fields and duplicate JSON keys are refused. The provider list requires full `hostname/namespace/type` source identity, exact version, target platform, and an artifact. A module entry requires a name, immutable 40- or 64-hex revision, archive subtree and full local graph: directory keys map module-call names to their resolved relative directory targets. `.` is the root. Every configuration directory and edge must match, be reachable and be acyclic. HCL and JSON are supported; duplicate keys at every depth of module JSON are refused before graph inspection. Remote/dynamic module sources, override files, mixed engine file precedence, hidden directories and hidden files other than `.terraform.lock.hcl`, state and variable files (regardless of suffix casing), links and non-text module payloads are refused. Registry sources belong in `registry_modules`, described below; there is no recursive public registry/Git resolver.

Every artifact requires an exact `url`, trusted ZIP `sha256`, and a bounded `provenance` reference. Optional `redirects` lists at most three exact subsequent HTTPS URLs; every listed hop must occur before the final response. Alternatively, an exact GitHub release URL can carry its decimal `github_repository_id`; only its first HTTPS response may supply one signed redirect to `release-assets.githubusercontent.com/github-production-release-asset/<repository-id>/<asset-id>`. That capability belongs to this artifact transfer, expires with the transfer, and grants no guest authority over the CDN. Further redirects are refused. Signed queries are accepted only on this server-issued redirect, have a bounded fixed key vocabulary, reject duplicate fields and decoded controls, and never enter receipts or diagnostics.

All ordinary URLs must already be canonical ASCII HTTPS with lowercase DNS host and implicit port 443. Paths are exact and allow only ASCII letters, digits, `_`, `-`, `.`, `~` and `/`; empty/dot segments, percent encoding, duplicate separators, userinfo, explicit ports, backslashes, fragments and caller queries are refused. No prefix rule broadens an ordinary URL. Requests are fixed GETs with `Host`, `User-Agent: maf-dependency-preparation/1`, `Accept: application/octet-stream`, `Accept-Encoding: identity`, and no body. Caller methods, headers and bodies are unsupported fields. Cookies, authentication, environment proxies, CONNECT and service discovery are unused. Every redirect receives the same checks. The transport rejects private, link-local, multicast and transition-address routes, checks all DNS answers, then connects to a checked numeric address with TLS hostname verification and no second DNS lookup.

Limits are 1 MiB manifest, 32 provider archives, 16 module archives, 16 registry module archives, 64 MiB per download, 256 MiB accumulated downloads, 32 KiB raw response head (status lines, headers and interim responses combined), 4,096 ZIP entries, 1 GiB expanded data per provider archive, 8 MiB expanded module data, 256 files per module bundle, 64 graph nodes, and 256 inventory records below one registry module call. Provider archives are checked in chunks rather than held in memory. The worker and parent share a fixed 180-second maximum; malformed or incomplete data never publishes an output. Complete SHA-256 verification precedes archive parsing. ZIPs are read as bounded data and never extracted by archive paths on the host. Receipts contain artifact identities, digests, each provider's per-file digests and `h1:` package hash, graph/file inventories, bounded decisions and the complete policy hash, omitting transfer URLs and response content. The receipt records the canonical manifest digest separately from a versioned `policy_contract` containing the preparation implementation SHA-256 and effective limits. `policy_sha256` binds both. Implementation text is normalized to LF before hashing, so checkout line endings do not change identity; any source edit or limit change does. Preserve the identified implementation with the receipt. Runtime warm reuse remains unsupported.

### Registry module graphs

Use `registry_modules` for registry sources such as Azure Verified Modules (AVM). Authored configuration keeps its `source` strings, `version` constraints and lock file. Nothing is rewritten to a local path. The guest still has no registry access: the base CLI configuration disables module registry discovery for `registry.terraform.io` and `registry.opentofu.org`, and egress stays CLOSED. [dependencies.terraform-avm.json](dependencies.terraform-avm.json) pins `Azure/avm-res-network-virtualnetwork/azurerm` 0.22.2, its nested `Azure/avm-utl-interfaces/azure` 0.6.0, and the azapi, modtm and random providers they require. Registry modules are Terraform-only; the preparer refuses them in an OpenTofu manifest.

That manifest is generated by [scripts/terraform_manifest.py](../../scripts/terraform_manifest.py) from [dependencies.terraform-avm.policy.json](dependencies.terraform-avm.policy.json), which names only provider addresses and registry-module sources with version constraints. [USAGE.md](USAGE.md#build-an-image-with-azure-verified-modules) shows how to refresh it and build the image.

Each entry names a `source` with its registry host, an exact release `version`, the 40-hex `revision`, and an `artifact` whose URL must be the codeload archive of that revision. `graph` maps each module directory in the package to its calls. A local call is `{"local": "<directory>"}`. A registry call is `{"registry": "<entry name>"}`. Preparation parses every configuration file in each declared directory and requires the declared edges exactly. Each registry call must carry a version constraint that admits the referenced entry's version. Local calls must stay inside the package and reach every declared directory. Registry references must be acyclic. Every `required_providers` entry and every resource, data or ephemeral type must match a pinned provider whose version satisfies the constraint. Constraints use `=`, `!=`, `>`, `>=`, `<`, `<=` and `~>` over release versions; a one-part `~>` is refused because the module and provider libraries read it differently. Only the declared directories are baked, without hidden files; examples, tests and repository tooling are omitted.

The receipt records each package's file digests and an `inventory`: the module manifest records Terraform writes below one call of that package. The prepared image copies the files to `/opt/maf-terraform/registry/<name>/` and refuses any missing or extra file. Before the image is published, the build runs the launcher against a probe root that pins every provider in the receipt at its exact version and calls every package at its pinned version, and fails unless offline `init` succeeds; it also refuses a mirror whose files are not executable, because a dropped executable bit would otherwise fail only later, at `validate`. At run time the launcher reads the staged project's module calls, follows local calls inside the project, and writes `modules.json` records for calls whose registry source matches a baked package. The record keeps the authored source spelling, and Terraform still compares it and the version constraint with the configuration. A call it cannot read, an unbaked module, an incompatible constraint, a missing child or provider, or a lock checksum mismatch fails initialization, so validation is INCOMPLETE.
